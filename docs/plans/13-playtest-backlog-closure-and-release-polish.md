# Plan 13 — backlog closure and release polish

Status: pending implementation after accepted Plan 11. Prepared 2026-09-05.
Owner: root or the Human-triggered specialist named in its execution prompt.
This plan precedes Plan 12 because polish may still change asset consumers.

## Outcome

The finished game should have no forgotten mandatory feature, misleading status
claim or unresolved blocker hidden under "polish." Turn the existing backlog
into an exact disposition ledger and fix bounded integration defects while
preserving the accepted game's character, comfort and save compatibility.

Read the vision, roadmap, full backlog, latest family reports, all affected
subsystem specs and accepted release evidence. Reinspect the current code and
assets; old card audits identify what to retest, not what still reproduces.

## Work sequence

The 2026-09-05 v0.20.1 intake's complete 17-item crosswalk is mandatory input.
Reconcile extended PT15/22/24 and PT33–42 individually. Book/bestiary/tabs and
no-scroll victory are UI-02 implementation commitments, not Plan-14 ideas.
Configured Mimic safety/reward guarantees and actual puzzle difficulty belong
to Plan 09. Six-sprite/new-friend candidates require their recorded Human
retain/refine/add/defer decisions; do not infer wholesale art rejection or
quietly retire approved missing consumers. XP remains separately decision-gated.
New defects discovered on FP-UI1/CORE2/CAMPAIGN extend the evidence, never erase
the old-build observations or automatically prove these cards accepted.

1. **Reconcile before editing.** Give every backlog card and required slice a
   disposition: Accepted, Deferred with explicit authority/return point,
   Superseded with replacement, or Declined by Human. Keep delivery separate
   from verification and release status. A candidate or unperformed family test
   is not Accepted just because its owner has finished a task.
2. **Walk the ordinary experience.** Inspect fresh start, Continue, first
   blocker/Power teaching, optional rescue, Hint, victory/Stay, Book, Sound and
   save/reopen. Then repeat the relevant controller/co-op/Garden paths. Look for
   confusing labels, duplicate announcements, lost focus, unexpected resets,
   uneven emphasis and delays between repeated actions. Preserve good moments.
3. **Choose bounded batches.** For each reproduced defect, name trigger,
   observed/expected behavior, owner, affected paths and test. Fix one coherent
   interaction or content family at a time. Required mechanics, missing enemy/
   friend coverage or generator families return to Plan 09; new economies,
   traversal rules, voices and persistent sticker editing need separate approval.
4. **Reconcile promised consumers.** Join final eligible assets to actual
   campaign/generated, UI, story, Garden, effect and animation consumers. Each
   must have a semantic ID, loading intent, rendition/metadata and evidence.
   A promised-but-unused asset is a missing integration or Human deferral, never
   an orphan to quietly delete in Plan 12.
5. **Update shared truth.** Refresh changed specs, backlog, release notes and
   user-facing help. Retain exact historical evidence, but clearly date it.
   Make one closure report; avoid a parallel issue tracker or copy of the backlog.

## Acceptance and evidence

- No open mandatory blocker is silently reclassified as cosmetic or deferred.
- Each closed slice links to source SHA, reproduction/check, result and honest
  platform/family scope. Small family samples report counts/examples rather
  than unjustified percentages.
- Focused regression tests cover changes; complete project/desktop checks and
  shared contracts pass. Use representative critical journeys and affected
  covering/pairwise cases, not a new exhaustive Cartesian test project.
- MOVE-01 comfort, stable travel ownership, exactly-once rewards, optional
  rescues, skip/replay and non-punishing co-op remain intact.
- Final closure report lives at `docs/playtests/PLAN13_CLOSURE.md` and lists
  all card IDs, dispositions, Human decisions, outstanding qualification rows
  and any returned work. It includes the exact consumer-freeze SHA after review.
- Root reviews/commits/pushes the checkpoint and verifies CI/web deployment.
  No extra portable release is required solely for Plan 13; RC-01 follows hygiene.

## Exit to Plan 12

Declare that all approved pointer-producing work is complete, with a concrete
catalogue/consumer snapshot. An approved follow-on changes this declaration:
reopen only the affected closure/retirement evidence. A freeze is never a reason
to reject a necessary correctness fix. Remaining hardware rows retain owners
and return gates and must be resolved or explicitly scoped at RC-01.
