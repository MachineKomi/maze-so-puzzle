## Where to send feedback

Reply in the existing Astra orchestration task with the filled details below.
Plain text is enough; a screenshot or short video is useful when available.
One issue per entry makes reproduction and ownership easier. You can report
issues immediately without finishing the whole checklist. Include enjoyable
moments and confusing moments as well as bugs.

```text
Build/version:
Portable filename or web URL; source SHA from the release note:
Windows portable or web:
Device, OS/browser, input method:
Maze name/number; ordinary run or tester:
Window size/orientation; motion and surface-quality settings:
What I did (short steps):
What happened:
What I expected:
How often it happens:
Impact (cannot continue / uncomfortable / confusing / minor):
Screenshot/video, if useful:
```

For movement, distinguish taps/holds, straight travel/corners/edge-of-maze,
and whether the actor, background or both seem uneven. Comfortable / tolerable /
uncomfortable plus a short note is useful. Stop an uncomfortable check.
Future camera zoom is planned for Plan 08 and is not expected in FP-UI1.

For celebration feedback, include Full/Reduced motion and Surface quality.
Static deliberately has no moving friends or falling confetti; small colored
confetti tips remain stationary at the top. Report whether that still feels
rewarding and whether all important content is readable on your device.

For a save problem, preserve the affected preview profile and the build. Report
the last successful save/reopen and current message before resetting anything.
Tester runs deliberately suppress ordinary rewards/persistence; use an ordinary
run in the isolated preview profile for those checks.
