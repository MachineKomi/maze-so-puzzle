## Creative north star

**Pocket-sized courage made visible.** This is a warm storybook maze where
friendship magic turns noticing, trying again, and helping into heroic action.
Silhouettes are rounded, chunky, and immediately legible; plum linework, broad
cel-like values, and controlled jewel accents give the pastel world handheld
JRPG clarity. Magic is optimistic and purposeful, never ornamental noise.

Five checks settle every visual decision:

1. Does it read at the smallest real display size before it impresses at 100%?
2. Is the subject and emotion clear from silhouette, face, and pose?
3. Does it use this world's shape, line, material, motif, and light grammar?
4. Is gameplay meaning preserved without relying on colour or motion alone?
5. Can its pixels be reconstructed, reviewed, budgeted, and rolled back?

## World grammar

### Shape and emotional tone

- Friendly and neutral forms start from circles, rounded rectangles, soft
  trapezoids, and broad teardrops. Challenge may add one or two controlled
  points, asymmetries, or diagonals; it does not replace the rounded core.
- Power expands the silhouette or clarifies the gesture. It does not sexualise,
  age up, armour over, or make a young character menacing.
- Primary read, secondary construction, and one accent must be separable at a
  glance. Tiny detail that survives only above presentation size is removed.
- Each character, friend, enemy, or prop gets one unmistakable silhouette
  anchor. Family consistency must not erase individual personality.

### Readability and rendering hierarchy

- Design from the smallest real delivery size outward. The first read is the
  outer silhouette and gesture; the second is two to four large colour masses;
  the third is construction and material; micro accents are last and expendable.
- Use one focal hierarchy. The face, required interaction, or narrative subject
  receives the clearest value edge and highest useful chroma. Supporting paint
  stays quieter even when it is decorative.
- Hair is grouped into locks, fur and feathers into two or three tufts/masses,
  foliage into clusters, stone into broad blocks, and fabric into broad folds.
  Detail that vanishes, sparkles unintentionally, or changes meaning at actual
  size is a defect, not added value.
- Finish should feel clean, hand-painted, tactile, and cel-painterly. Reject
  generic airbrushed gradients, plastic 3D/mobile gloss, vector-flat drift,
  photographic noise, and equally sharp detail everywhere.
- Family cohesion comes from shared massing, contour, value, material,
  perspective, and motif rules—not from giving every subject the same face,
  accessory, palette allocation, or personality.

## Drawing and rendering rules

### Lines and edges

Human calibration correction (2026-09-03): the deterministic v08 comparison is
rejected as a rendering-direction choice. It demonstrated locality at enlarged
crop scale, but at delivery size it read as a near-black post-process stroke on
historical pixels. `storybook-local-contour-v1` therefore means **authored into
the drawing**, including new interior massing, values, material painting and
edge decisions. It must never be implemented by dilating/recolouring the old
silhouette and calling that a replacement. The next gate compares independently
authored directions A/B/C; the Human's later per-family selections are recorded
below. None of the comparison boards is a production master or runtime authority.

- `storybook-local-contour-v1` is the `mgjrpg-02` actor/prop contour grammar.
  Every contour section derives from the nearest interior material/colour region
  it encloses and then shifts darker and slightly richer while remaining
  harmonised toward the world's plum inks. It is not one black perimeter and is
  not a sampled rainbow fringe.
- Reserve `ink-900` for pupils, mouths, deep occlusion, and critical separation.
  Pure black, one dead uniform perimeter colour, random rainbow edging, gaps,
  semitransparent contour fragments, and unrelated outline hues fail.
- Contour colour changes occur only at a meaningful material boundary or
  construction joint. Merge tiny edge islands into the dominant neighbour;
  never dither, alternate pixel by pixel, or create a soft chromatic halo.
  Interior region separators use the darker local colour of the material joint;
  they are never arbitrary black dividers pasted across unrelated surfaces.
  Against both the nearest fill and the representative review backgrounds, an
  essential silhouette segment targets enough value separation to remain
  continuous at delivery size. Rebalance the adjacent fill/value mass before
  darkening a whole perimeter. A non-facial material contour targets roughly
  38–55% HSL lightness, stays visibly chromatic, and may fall below 35% only for
  a measured critical separation. `ink-900` should occupy at most 5% of the
  outer perimeter and has a hard 10% maximum with written accessibility
  justification. Pure black remains zero.
- Terrain uses painted material boundaries, not character outlines. In-world
  actors, objects, and pickups never receive a white sticker halo. Semantic UI
  icons, badges, prompts, and reaction glyphs may use one deliberate cream-white
  paper-cut edge around their local-colour inner contour; rewards may use the
  same signal-layer treatment when their context is UI rather than world space.
- Transparent edges carry colour-dilated subject RGB, never white, gray, black,
  checkerboard, or chroma-key contamination.

### Value and light

- Use three broad value groups: local midtone, grouped shadow, and light. A
  small accent highlight is added only when it explains a material.
- Character/prop source reference is soft upper-left/front, approximately 315
  degrees azimuth and 45 degrees elevation. It is gentle form modelling, not a
  scene-specific spotlight.
- Static cutouts have no floor cast shadow, broad glow halo, or painted contact
  shadow. Runtime owns contact shadows, emitted glow, wall depth, and resolved
  directional lighting.
- Floor, wall, hazard, and dressing paintings are near-neutral diffuse/albedo.
  Crack occlusion is allowed; directional cast shadows and spotlights are not.
- Emissive objects retain a readable unlit base so disabled/reduced-motion
  states remain clear.
- Normal and powered/glowing static states keep the same silhouette, pivot,
  baseline, safe area, and alpha footprint. Apparent light begins inside the
  depicted volume; Plan 02 owns external halo, rays, motes, pulses, and animated
  emission, so a blurred duplicate never substitutes for a designed state.

### Perspective and proportion

- Field actors and carried props: front three-quarter, slightly elevated, no
  lens distortion, common ground plane.
- Doors and cage fronts: near-frontal orthographic with only enough top plane to
  explain volume. Portals and holes: top-down orthographic.
- Floors, walls, hazards, dressings: strict top-down periodic orthographic.
- UI icons: flat or shallow three-quarter; one view per family. Story art may be
  cinematic, but identity and material landmarks remain locked.
- Ame field model: 2.9–3.1 heads; story/key art: 4.5–5.0 heads as an explicit
  richer tier, not a redesign. Friends: 1.6–2.0 heads. Small enemies: 1.5–2.25
  heads, up to 2.75 for large rounded masses.
- Faces keep visible brows, stable pupils/catchlights, and simple mouths. The
  required principal-character expression set is neutral, joy, determination,
  worry, surprise, sadness, relief, and annoyance.
- Poses use stance, direction, eyeline, and clear gesture. No pin-up posture,
  adultised anatomy, realistic suffering, or costume emphasis inappropriate
  for a child.

Application text stays a rounded, friendly, compact humanist sans. `Fredoka`

### Visual-layer material separation

1. **World/content layer:** cel-painterly actors, objects, terrain, and story art
   with local-plum contours and materially truthful surfaces.
2. **Functional surface layer:** opaque or near-opaque paper, enamel, cloth, or
   restrained frosted-magic panels. Dense copy never sits on stacked glass.
3. **Signal/sticker layer:** literal semantic UI icons, badges, prompts, emotion
   glyphs, and selected UI rewards with one cream paper-cut edge.
4. **Accent/effect layer:** rare transparent glints, magic, particles, and
   transitions owned by Plan 02.

The relationship is “paper-cut signals over magical surfaces over painted
world,” not “make everything a sticker” or “make everything translucent.”

### Maze-native interface surface grammar

The interface is authored game art, not a generic web dashboard decorated with
sprites. Its primary magical-glass surface has a milky white or pearl,
near-opaque body; a quiet centre behind text; a soft luminous inner rim; a
material-local plum, lavender, mint, coral, or warm-gold outer edge and shallow
shadow; and at most one sparse corner or edge ornament. It should feel like
frosted storybook crystal or polished magical enamel rather than clear browser
glass. Literal backdrop blur is optional implementation detail, never the
identity: every surface has visually equivalent `full`, `lite`, and `static`
recipes, and the persistent HUD never continuously blurs the moving maze.

| State | Required authored change |
| --- | --- |
| Default | Quiet readable body, inner rim, clear edge, one stable focal hierarchy |
| Hover | Small rim/edge or lift response; no layout shift and no meaning by motion alone |
| Focus | Unmistakable keyboard/controller focus ring integrated outside the art edge |
| Pressed | Brief inward value/position response with the label and icon still stable |
| Selected | Persistent shape, plate, notch, or badge change as well as colour |
| Disabled | Lower emphasis while preserving text, silhouette, and state comprehension |

Dense text uses the most opaque quiet-centre recipe. Celebration, blocker, hint,

### Transparency and colour handling

- Normalized masters are flattened lossless sRGB RGBA PNG with straight alpha,
  beside any layered editable source. Record missing profiles; do not invent one.
- Prefer native alpha. If extraction is unavoidable, preserve the RGB original,
  remove edge-connected and enclosed background separately, inspect all holes,
  and record the mask/edit. Never ship a chroma-key background.
- Resize in premultiplied alpha, return to straight alpha, and dilate subject RGB
  2–4 runtime pixels beneath transparency. Keep at least two fully transparent
  outer pixels; strict-v1 new derivatives use four.
- Reject matte fringe, dust, pinholes, clipped flourishes, translucent solid
  cores, and erased pale detail. Inspect on paper, black, gray, magenta, cyan,
  and busy terrain at 0.5x, 1x, 2x, and 400% edge zoom.
- Static field art has neutral front/top form modelling and no baked directional
  cast shadow. Plan 04 supplies scene direction and wall depth.

## Provenance and anti-drift workflow

`src/artCatalog.ts` selects runtime pixels. Hand-reviewed JSON under
`docs/source-assets/records/` is source authority. The sorted generated manifest
cross-checks records and files, fingerprints both runtime catalogue modules, and
the validator resolves every literal rich-catalogue `sourceRecordId`; it is not
edited by hand. Full semantic ID/version/URL/status comparison still belongs to
TypeScript tests and review until the catalogue exposes a structured export, so
`art:check` reports that limitation rather than implying stronger automation.

Lifecycle axes are independent:

- `runtimeStatus`: active, dormant, deprecated, superseded, or source-only.
- `sourceStatus`: source-backed, partial, or legacy-runtime-only.
- `approvalStatus`: historical, candidate, pending-human, design-approved,
  approved, or rejected. `design-approved` records identity/construction only;
  only `approved` plus named runtime-publish evidence and reviewed rights can
  authorize a public derivative.

Being active never implies approval. Every new asset records stable ID/version,
recipe, exact prompt and fidelity, generator facts only when known, output ID,
reference roles and SHA-256, immutable source, human edits, rights review,
geometry, derivatives, encoders, encoded/decoded bytes, loading phase, and
rollback pointer. Repository first-seen time is never called generation time.

Production sequence:

1. Choose one approved rendering/family anchor and a separate identity anchor;
   write the family DNA card and label every reference by its single role.
2. For a new identity-bearing asset, generate exactly two independent candidates
   from equivalent pinned inputs. Neither candidate sees the other. Preserve both
   and record selection/rejection reasons. One objective-defect correction is the
   maximum before returning to the brief or Human decision.
3. For an approved identity's pose, expression, or state, generate directly from
   its selected source plus the family rendering anchor. Never use an expressive
   state, cleaned cutout, correction, derivative, or rejected candidate as the
   next generation's identity source.
4. Change one declared variable per iteration; archive every candidate and
   rejection. Existing A/B/C Ame v02 history remains truthful and is not
   retroactively rewritten by the two-candidate rule.
5. Run the canary set before approving a global recipe change.
6. Generate to source-only paths; create versioned normalized derivatives.
7. Validate schema, hashes, alpha, bounds, safe zones, colour, pairings, seams,
   bytes, decoded memory, and actual-size contact sheets.
8. Obtain named human approval. Approval of an identity source does not approve
   its cutout, derivative, animation frames, runtime pointer, rights, or release.
   Only then switch one family catalogue pointer through its own gates.
9. Retain previous pixels and reversal instructions for one release. Cleanup is
   a separate, proved-dead change.

Bootstrap the pinned art environment with
`python -m pip install -r requirements-art.txt`. The repository commands are
deliberately explicit: `npm run art:test`; `npm run art:check` for a read-only
gate; `npm run art:manifest -- --write` for the only manifest write; `npm run
art:build -- --id <record-id> --profile <profile-id>` for a staged,
no-overwrite derivative; `npm run art:proof` for the historical Candidate-C
canary; `npm run art:proof:mgjrpg02` for the rejected contour-assay lineage;
`npm run art:proof:mgjrpg02:options` for the immutable authored-direction slate;
and `npm run art:proof:mgjrpg02:selection` for the current bounded selection
follow-up packet.
Existing proof derivatives must be moved aside or deliberately removed before
a rebuild—the builder never silently replaces one. The record, manifest, and
proof-index hashes are the review identity, not an informal filename alone.
