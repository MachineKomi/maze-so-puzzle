# `mgjrpg-02` runtime publication

This directory is the machine-readable handoff from approved immutable source
art to the semantic runtime catalogue. It is generated by
`scripts/art_pipeline/mgjrpg02_publish.py`; filenames never establish identity,
approval, lifecycle, or catalogue ordering.

The authority chain is:

1. Immutable generator output plus exact batch prompt, output ID, ordered
   reference roles, source hash, and original disposition under
   `docs/source-assets/production/mgjrpg-02/`.
2. The forward-only Human runtime-publication decision at
   `docs/source-assets/calibrations/mgjrpg-02/v06/human-decision.json`.
3. `mgjrpg-02-plan03-runtime-map.json`, which explicitly joins each approved
   run ID to one stable semantic ID, delivery profile, catalogue target,
   lifecycle state, prior rollback URL, and versioned output URL.
4. One strict-v2 source record per selected source and
   `mgjrpg-02-plan03-publication-report.json`, which records measured output
   hashes, bytes, decoded upper bounds, alpha/seam results, and geometry.
5. `src/generated/mgjrpg02Art.ts`, which is the generated TypeScript projection
   consumed by `src/artCatalog.ts`.

Run the pipeline from the repository root:

```powershell
npm run art:publish:mgjrpg02:plan
npm run art:publish:mgjrpg02
npm run art:publish:mgjrpg02:check
```

The plan command verifies exact selection membership and all immutable source
hashes before writing the forward decision/map. Publication stages and validates
the complete set before exposing any runtime file, then uses a no-replace
filesystem primitive. It never overwrites, moves, deletes, or creatively changes
an approved source. The check command recreates every derivative in a temporary
directory and byte-compares it with the published file.

Delivery processing is limited to colour-space normalization, declared flat
matte recovery or native-alpha preservation, aspect-preserving registration,
premultiplied-alpha resize, tiny-component cleanup, hidden-edge colour dilation,
exact-black normalization to Maze ink-plum, periodic preparation, and recorded
WebP encoding. Authored colour-aware contours, identity, expression, materials,
motifs, and proportions come only from the selected immutable source.

`active` means an existing runtime semantic pointer is switched by Plan 03.
`dormant` means a stable, formally catalogued future asset with no current level
placement, preload, mechanic, balance, or progression effect. Application icon
and Batch 21 title/home/logo studies remain deferred to Plan 11. Old runtime
files remain in place as rollback dependencies; the retirement ledger proposes
their eventual Plan 12 disposition but does not make them deleted or archived.

Two semantic migrations are deliberately not inferred from image filenames:
`green-tea-skeleton` is a dormant rescue friend and never an enemy, while
`bubble-ring-blade` is the current weapon identity and `bubble-bow` survives
only as a one-way historical saved-content alias. The Batch 15 Normal Boots
drawing is published as the active `splash-boots` pickup and replaces the old
boots delivery rather than becoming a second dormant footwear identity. Violet
Moon remains the active third portal pair; Sunny Diamond and Violet Spade Bloom
remain dormant.

The final publication contains 144 derivatives totalling 9,366,734 encoded
bytes and 107,937,792 decoded-RGBA bytes as a theoretical all-files upper bound.
The 100 active entries total 7,068,346 encoded / 92,471,296 decoded bytes; the
44 dormant entries total 2,298,388 encoded / 15,466,496 decoded bytes. These
figures describe files, not simultaneous browser residency. The generated
manifest inventories the complete before-plus-publication runtime as 269 images
/ 48,540,161 encoded bytes / 290,949,024 decoded bytes.

Fifty-six non-Ame actor records deliberately defer semantic face/eye/ground
landmarks rather than fabricating them from alpha bounds. They do not block the
locked static pivots, canvases, or live Plan 03 review, but they do block Plan 05
animation and automated cage-face masking until manually registered. The exact
rows and fields are in the publication report's `deferredGeometry` array.

The initial uncommitted run exposed and corrected one processing defect before
publication: the opaque-terrain periodic helper discarded alpha from four
sparse dressing overlays. Rejected transient hashes and the bounded
RGBA-preserving correction are recorded in
`mgjrpg-02-plan03-transparent-dressing-defect.json`. No approved source pixels
or pre-existing/superseded runtime asset were changed.

`mgjrpg-02-plan03-visual-integration-report.json` records the production-preview
screens, exact viewport captures, a normal victory/unlocked-reward exercise,
144-URL HTTP exercise, visible-image checks, and console result. The checked-in screenshots are deliberately not duplicated:
the capture paths point to ignored local evidence under `artifacts/art-proofs/`.
`mgjrpg-02-plan03-validation-report.json` records the exact art, application,
desktop, performance, and browser commands, distinguishing the four reproduced
gameplay-solver timing warnings from Plan 03 regressions.
The publication test suite separately schema-validates and reconciles all 116
rollback-hold ledger entries with the manifest and runtime map, proves every
held file still exists at its recorded hash and byte count, and rejects an
archive target beneath live `public/`.
