## Maze So Puzzle Feedback

### Performance

* On iPad, larger mazes have noticeable performance issues: movement feels less smooth and more stuttery. Smaller mazes seem less affected.
* The iPad UI itself looks great: the layout is good and there are very few, if any, visual/UI complaints.
* A relatively new Samsung phone does not show the same performance issues, despite both devices running the web app. This may be device-spec related, but optimisation should be improved so performance problems are less severe on lower-spec devices.

### Mobile UI and controls

* The new directional pad / analogue-stick control is a huge improvement.
* On phones, the UI feels too scrunched and rearranged, with too much scrolling required. Prefer the same general layout as iPad and desktop, with smaller icons and UI elements rather than moving everything around.
* Collapsing secondary information into a menu on mobile is fine, as long as the menu is present, attractive, and smooth. The current collapsible UI has a little jank.
* Touch controls can accidentally select on-screen text and icons, causing blue text-selection highlights. Prevent text and UI elements from being selectable during gameplay.

### Movement interruption issue

* When holding and dragging the analogue control, any event that interrupts movement—such as opening a door or starting a battle—requires the player to release their touch and touch/drag again before movement resumes.
* Prefer held directional input to remain active through these interactions, allowing the character to continue moving in the held direction once the interruption ends.

### Directional pad appearance

* The directional buttons overlaid on the square movement pad look a little ugly.
* Prefer subtler, built-in-looking directional indicators rather than visible button boxes.
* Possible approach: use larger dark purple or black outline arrows directly on the pad—one pointing in each direction—with no boxed button backgrounds.

### Bestiary

* The current bestiary looks poor when most entries are locked because every unseen enemy shows a question mark and repeated placeholder text.
* When no enemies have been encountered, show a friendly empty-state message, e.g. “Ooh, go explore and battle something before you can see it here,” perhaps alongside a single enemy silhouette.
* Once enemies are encountered, show only the entries the player has discovered.
* Keep discovered enemies sorted in their natural ID/order rather than encounter order.
* Add a progress counter, such as “2 / 20 discovered,” so players can see overall bestiary completion without displaying every undiscovered entry.
